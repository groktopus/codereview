# Frozen evaluation corpus v1 (QM-1)

The frozen corpus is a versioned set of 41 merged pull-request cases across two
public repositories. It exists so later work can bind review outputs, labels,
and baseline arms to exact immutable case identities. It is not a quality
measurement: it contains no human labels, no predictions, no model output, and
no claim that any review is correct.

Dataset files live in [examples/evaluation/frozen-corpus-v1](../examples/evaluation/frozen-corpus-v1):

| File | Purpose |
|---|---|
| [corpus.json](../examples/evaluation/frozen-corpus-v1/corpus.json) | The `review-evaluation-corpus.v1` case contract consumed by `scripts/evaluate_reviews.py`. |
| [source-manifests.json](../examples/evaluation/frozen-corpus-v1/source-manifests.json) | Per-case source records: merge identity, changed-path diff hashes, snapshot identity, evidence metadata hash, and gap counts. |
| [manifest.json](../examples/evaluation/frozen-corpus-v1/manifest.json) | Dataset version, content hashes, changelog, provenance, rights, retention, contamination, sampling, split policy, counts, and per-case inventory. |
| [REPORT.md](../examples/evaluation/frozen-corpus-v1/REPORT.md) | Generated counts by repository/split/family and the per-case table. |

## Counts

| Repository | development | heldout | challenge | total |
|---|---:|---:|---:|---:|
| `groktopus/codereview` | 9 | 7 | 5 | 21 |
| `magnus919/SlopSearX` | 9 | 6 | 5 | 20 |
| **total** | **18** | **13** | **10** | **41** |

The corpus declares the `risk_enriched_challenge` sampling frame because it is a
purposive selection, not a random or prevalence sample. Five documentation-only
cases are candidate zero-finding controls. Evidence status is defined as:
**complete** (every required obligation evidenced, no required gaps), **bounded**
(policy-capped context with the changed diff present; window/count limits may leave
required gaps, recorded in `snapshot_gap_counts`), or **incomplete** (changed diff
or required projection truncated/missing; not comparable to complete cases). Seven cases have incomplete snapshot
evidence, including one with repeatedly truncated diffs. No label asserts that
a control is clean or that an incomplete case has no defects.

## Frozen identity

Each case fixes:

- repository owner/name and merged PR number;
- the merge commit, its first parent as `base_sha`, and its second parent as
  `head_sha`;
- a `snapshot_id` computed by
  `pr_review_harness.snapshot.collect_snapshot` in PR merge-base mode with the
  checked-in profile and `profiles/ordinary-review-limits-v3.json`;
- the profile ID, version, and canonical JSON SHA-256;
- a source-manifest ID and canonical SHA-256 over the checked-in source record.

The profile is the checked-in profile used to freeze the case. It is not a claim
about which profile was in force when the pull request merged.

The source record binds the changed-path diff SHA-256 values, snapshot identity,
the SHA-256 of sorted evidence metadata, and gap counts. No repository source
body is copied into the dataset. `snapshot_id` proves base/head/profile
identity; it does not prove that every context byte was captured, so gaps are
recorded per case. The harness `snapshot_hash` is not stored because it includes
the local absolute repository path; the portable `snapshot_id` plus the source
record's evidence metadata hash bind the snapshot instead.

The checked-in files were generated by
[scripts/build_frozen_corpus_v1.py](../scripts/build_frozen_corpus_v1.py), which
uses only local Git objects and never calls a model or provider:

```sh
python scripts/build_frozen_corpus_v1.py \
  --slopsearx-repo /path/to/SlopSearX \
  --codereview-repo /path/to/codereview
```

The checked-in corpus SHA-256 is recorded in `manifest.json`; regenerating on the
same commits, profiles, and limits produces the same identities. The report and
manifest are derived from the corpus and source catalog and must be regenerated
with them.

## Provenance, rights, and retention

Both repositories are public and MIT-licensed. The dataset stores identities,
paths, hashes, and metadata only; it does not redistribute source files,
credentials, prompts, provider bodies, or review text. No private project,
target-application payload, or secret is included.

The corpus is versioned and immutable. A case is never silently replaced.
Corrections and additions require a new `dataset_version` and changelog entry;
the previous manifest and source hashes remain in Git history. The dataset is
retained with the repository and is bounded to metadata so it can be reviewed
without cloning either repository.

## Split policy

- `development`: may be inspected during harness development, but is not
  held-out evidence.
- `heldout`: must not be used to tune prompts, profiles, thresholds, context
  policies, or model choice, and individual failures must not be inspected to
  guide tuning. Report aggregate results only.
- `challenge`: risk-enriched merged PRs. Its rates are challenge-set rates and
  must never be reported as natural prevalence.

Families never cross splits. Assignment was purposive and fixed before snapshot
collection; no model output, review finding, or quality label informed it.

## Contamination and limitations

`groktopus/codereview` is the harness's own public development repository; `magnus919/SlopSearX` is the separate public pilot target they share maintainership of. Models and
operators may have seen them. `heldout` means withheld from this curation's
selection analysis, not proven unseen by every model or prompt. No prompt,
profile, threshold, or model was tuned against this corpus in QM-1.

The corpus cannot establish:

- defect or finding prevalence, because it is deliberately enriched and
  purposively selected;
- human precision, recall, severity, or introducedness, because it has no
  labels or adjudication;
- cross-language generality, because it covers two repositories with shared
  maintainership and a Python/Rust transition;
- review correctness or model quality, because no review arm was run;
- complete evidence for every case, because snapshot gaps and truncated diffs
  are explicitly present;
- that a control is clean or that an incomplete case contains a defect.

## Validation

`tests/test_frozen_corpus.py` validates the corpus with the same
`validate_corpus` contract used by `scripts/evaluate_reviews.py`, checks the
exact counts, repository/split coverage, family split isolation, per-case source
hashes, dataset content hashes, and the required provenance/split-policy
records. The evaluator itself still requires predictions and labels for a full
run; this dataset intentionally supplies neither.
