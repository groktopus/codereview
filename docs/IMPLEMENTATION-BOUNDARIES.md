# Initial implementation interface contract

Root-approved build/test instruction: user 2026-09-26 “Let’s build and test against recent commits”. Read-only historical commit adapter is added to PR interface; local Git refs do not claim current GitHub freshness. Historical runs use freshness CURRENT meaning the specified local immutable snapshot verified unchanged, freshness_basis HISTORICAL_SNAPSHOT; they never imply current PR review or merge eligibility. PR mode must check remote expected head at end; unknown fails approval. Output mode initial read-only, no head-code execution. Operational defaults proposals: deadline 300s/run, max concurrency 3, max calls 12, max retries 0, max context 300000 bytes, per-task input 64000 bytes, output 16000 bytes, output tokens 1800; monetary cost unknown explicitly, no monetary cap enforced without configured price. These are pilot ceilings, not adopted quality targets.

Shared implementation modules use plain JSON-compatible dicts and explicit validation; record contracts version 0.1. All functions reject invalid inputs without secret-bearing diagnostics.

## snapshot.py (snapshot/CLI agent)
- `collect_snapshot(repo: str, base: str, head: str, profile: dict, limits: dict) -> dict`: resolve full SHAs; immutable snapshot `{snapshot_id, repository, base_sha, head_sha, profile_version, profile_hash, inventory, evidence, gaps, snapshot_hash}`. inventory entries `{unit_id,path,old_path,change,kind,diff,evidence_ids}`; evidence mapping ID -> `{evidence_id,path,content,line_start,line_end,content_hash,source_kind,trust,snapshot_id}`. Include diff with line anchors AND bounded full-file context from base/head, trusted guidance from BASE only, profile allowlist context (with snapshot/profile provenance). Avoid symlinks, submodules, binary executions, package hooks. Explicit gaps for truncated/missing content. Snapshots generated IDs deterministic hash. profile defaults MUST NOT come from head-controlled file; external profile explicitly passed.
- `recent_commits(repo: str, count: int) -> list[dict]`: first-parent non-root historical pairs `{base,head,subject}` bounded count, no duplicate merge and constituent comparison. Latest first; record merges first-parent semantics.

## engine.py / planner.py (core agent)
- `plan_review(snapshot: dict, profile: dict, mode: str='AUTO') -> dict`: mode/routing reasons, coverage obligations and `tasks` each `{task_id,scope_id,task_kind,lens,unit_ids,evidence_ids,required,question_version}`. Respect risk floors, docs/config/code differences, ignore only trusted rules with explicit denominator. Required project-check results never inferred PASS; absent evidence NOT_STARTED. Broad diff doesn't hide skipped units; bounded batching allowed.
- `run_review(snapshot: dict, plan: dict, profile: dict, provider, decision_provider, limits: dict, output_dir: str, run_id: str, resume: bool=False, freshness_check=None) -> dict`: parallel bounded workers using provider.review(task,evidence,limits); optional decision `decision_provider.assess(question,text,limits)` advisory context/risk classification with deterministic floors. Enforce atomic preflight and unsupported primitive before calls. Append ledger, preserve complete/no-finding vs incomplete, reconcile locations/evidence, independent bounded semantic adjudication through provider.adjudicate(candidate,evidence,limits) if configured/capable; known deterministic finding separate. Do not claim evidence hashes prove semantic truth. Invalid/contradictory candidates unresolved; advisory recommendation only. Preserve blocker IDs. Budgets checked/reserved before every call, including adjudication; retries bounded and counted. Coverage satisfaction must require valid task result and evidence coverage. Missing providers do not complete required semantic scopes. Atomic report/result writes; resume validates request/snapshot/profile/limits/provider identity, no second inference for completed run, refuses mismatched/corrupt ledger. `freshness_check()` returns CURRENT/STALE/UNKNOWN plus expected/observed identities. Historical scope requires explicit basis. No publication.
- `render_report(result: dict) -> str`: metadata followed exactly four report categories; evidence IDs/paths/lines, disposition/coverage/freshness, limits, unknown costs and context gaps. Deterministic rendering sufficient; no extra editorial call required.

## providers.py (provider agent)
- `OpenAIProvider(config: dict)` config `{kind:'openai',base_url,model,api_key_env,timeout_seconds,...}` lazy credentials process env only. `identity` property dict (no secrets), `review(task,evidence,limits)->dict` specialist payload `{finding_candidates:[],context_gap_proposals:[],coverage_notes:[]}`; each candidate path line/title observation consequence rule_or_contract severity reasoning_kind evidence_refs introducedness. Native endpoint actual response validated; no silently repaired/truncated JSON or inferred missing fields. Optional `adjudicate(candidate,evidence,limits)->dict` claim semantic assessment, supported vs unclear, native capability preflight. Return usage metadata alongside payload; response primitive explicit. Could return `{payload:...,usage:...,provenance:...}`; engine normalizes this wrapper.
- `DecisionProvider(config:dict)` native Laya/Jev contracts verified from local SystemOne skill/scripts and official docs; `identity`, `assess(question:str,text:str,limits:dict)->dict` outcomes conservative, rawnative hashes/provenance, no semantic-equivalence/confidence claims. Optional provider unavailable never lowers deterministic floor. GLiNER adapter only if native service verified; never fabricate.
- `load_provider_config(path: str|None)->dict|None`; callers factory `make_provider(config)`; `make_decision_provider(config)`; no secrets in configuration (reject literal keys). Native unsupported primitive rejects before dispatch.

## cli.py (snapshot/CLI agent)
`main(argv=None)->int`: argparse `review --repo --base --head --profile --provider-config --decision-config --output --mode --run-id --resume --json --dry-run`, `recent --repo --count --profile ...`; all commands lazy auth/help. Profile external JSON; provider-free mode produces real evidence/coverage with INCOMPLETE for required semantic scopes, not fake clean review. Supports GitHub Actions environment/event adapter WITHOUT write API; event parsing trusted target metadata and remote-head freshness via gh with bounded argv subprocess. CLI 0 valid durable terminal report including INCOMPLETE, 2 invalid preflight request/config, 1 failure with no valid durable report. Dry-run performs no writes/calls; prints request preview. stdout JSON only when --json. recent batch returns artifact paths and per-run dispositions, never claims calibrated quality. No repository writes.

This is an operational setup correction, not a quality threshold. Configured monetary caps reject because monetary reservation is unsupported. Total context accounting currently reserves specialist request bytes; adjudication/native requests are individually bounded and call-count bounded but not charged to that specialist byte ledger. NFR-002 total-context accounting is therefore partial for all-stage spend.
