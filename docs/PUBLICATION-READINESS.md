# GitHub review publication readiness

**Decision: NO-GO. Publication remains disabled.** This record distinguishes local adapter evidence from hosted proof and states what must be produced before a narrowly scoped publication can be considered. It does not authorize a write.

## Evidence now available

The existing [`pr-review publish` command](CLI-PUBLISH-PREVIEW-MIGRATION.md) renders a validated preview and does not read GitHub credentials or write externally. `GitHubActionsPublicationAdapter.admit()` performs bounded API-bound checks for the open PR, analysis and publisher runs, selected result artifact, artifact digest, and exact result binding, then constructs a `PublicationAdmission` containing the PR/head/base, run identities, artifact hash, and admission-evidence hash ([implementation](../src/pr_review_harness/actions_publication.py)). The fake-transport suite exercises artifact admission, receipt handling, history limits, and one-shot submission behavior ([tests](../tests/test_actions_publication.py)); its new `admission_only` case proves the candidate can be built with read-only scopes and makes no POST or upload.

There is limited historical hosted read-only evidence for the analysis workflow: [run 36294682123](PRODUCTION-DELIVERY.md) checked PR 477's head and uploaded its result artifact, but ended `PARTIAL` / `INCOMPLETE`. This was not a publication admission run or a publisher identity canary. The publisher workflow still has an unconditional hard stop at `if: ${{ false && vars.PR_REVIEW_PUBLICATION_ENABLED == 'true' }}` ([`.github/workflows/pr-publish.yml`](../.github/workflows/pr-publish.yml)). No hosted publication, publisher credential-provider, pre-POST receipt persistence, or write-path proof is claimed.

Specialist detection evidence remains insufficient. Sanitized PR-457 run 36468167383 recorded six valid specialist reports with zero findings; PR-464 runs 36401670945 and [36517763840](experiments/model-only-shadow-run-36517763840.md) each recorded ten valid zero-finding reports. In 36517763840, the writer and upload stages projected `success`, but the shadow audit was `incomplete` / `no_writer_candidate`; Jev and both auditors made zero calls. This is green transport/report parsing paired with an incomplete audit, not a completed comparison or a semantic-quality result. The sanitized preflight binds that run to runner `c05ab8f`, before merged PRs #126 and #127. PR #126 added the artifact-recovery preview; PR #127 merged local-only private per-task diagnostics (not uploaded). These improve recovery and observability without closing the review-quality evidence gap. A next provider-free control can use fixed synthetic expected findings and scripted outputs to check that an omitted finding is surfaced as a test-oracle miss and that incomplete outputs remain incomplete. Such a control would validate sensitivity/safety plumbing only; it would not establish real-defect detection, recall, calibration, or production quality. The existing human-adjudicated gold evaluation remains unchanged.

## Blocking gaps and acceptance evidence

| Gate | Current state | Evidence required to close |
|---|---|---|
| Verified runtime identity and least privilege | **Missing.** The adapter requires a trusted `PublisherCredentialProvider` returning a canary-backed `VERIFIED` identity. No runtime provider is integrated. `GITHUB_ACTOR` or a local assertion is not identity evidence; the read-only canary explicitly reports publication capability unavailable ([`ACTIONS-RUNTIME.md`](ACTIONS-RUNTIME.md)). | A protected, read-only hosted canary artifact bound to the publisher run must show API-derived identity and exact repo/workflow/run/attempt/ref/SHA bindings, token permission observations, and safe failure behavior. Then implement a provider that consumes only the validated trusted runtime evidence and returns a short-lived repository-scoped credential with the requested permission set. Tests must show read-only admission works without write scope and that missing, mismatched, expired, or broader-than-policy credentials fail closed. |
| Owner authority and target selection | **Missing.** No owner has approved a publication for a specific result. A valid admission is evidence about provenance, not approval to publish. | Record the named repository owner/approver, operator, exact repository ID, PR number, base/head SHA, upstream run ID/attempt, artifact ID/digest, disposition/event, canonical review-body hash, and one-attempt limit. Approval must be explicit and bound to those immutable values; any changed value requires new approval. |
| Hosted run and artifact admission | **Partially implemented in local adapter tests; hosted path unverified.** `admit()` checks current PR/run and artifact evidence, but `pr-publish.yml` does not wire it into a publication candidate job. | A protected hosted, read-only candidate run must retrieve only the selected artifact and emit a sanitized receipt containing identifiers, hashes, and status. Preserve the run logs/artifact and demonstrate exact success plus stale head, wrong run/attempt, missing/ambiguous/expired artifact, digest mismatch, and API-unavailable cases all reject or report `UNKNOWN`. No review/comment POST may occur. |
| Pre-POST receipt and replay history | **Fake-backed core only; no hosted uploader/history integration.** The design requires an acknowledged `SUBMISSION_STARTED` receipt before a single POST and complete bounded history reconciliation ([`ACTIONS-PUBLICATION-DESIGN.md`](ACTIONS-PUBLICATION-DESIGN.md)). | On a protected hosted rehearsal, prove the official artifact uploader acknowledges a receipt on the exact publisher run before the POST boundary is reachable. Show failed or ambiguous upload prevents POST; prior/missing/expired receipt, incomplete pagination, API errors, or ambiguous submission remain `UNKNOWN` and cannot trigger a retry. Retain publisher-run artifacts for the full reconciliation horizon. |
| One-comment canary | **Not authorized or implemented.** A read-only canary cannot prove the write path, and passing local tests do not grant approval. | After all prior gates pass, obtain separate owner approval for exactly one non-blocking `COMMENT` on the exact admitted head and body hash. Use the least-privilege writer identity; capture the GitHub response and independently read back one matching review ID, actor, commit, event, marker, and body hash. Bound it to one attempt; any ambiguous result stops further publication pending owner-led reconciliation. |
| Disablement and rollback | **Current containment is effective:** the publication job is hard-disabled and has empty permissions. | Keep that hard stop until the owner approves a reviewed enablement change. The rollback control is to restore the hard-disabled condition, remove write permissions/credentials or revoke the app installation, and verify the workflow cannot dispatch a writer. A posted comment may already have notified users; containment cannot undo that effect. Any removal or correction requires a separate owner-directed incident decision. |

The owner must also name the operator responsible for `UNKNOWN` reconciliation and define artifact access/retention and finite run, page, byte, and deadline limits before any canary. No automated check, fake transport, read-only hosted result, or model output can substitute for that owner decision. Until every gate has its named acceptance evidence, publication stays disabled and the decision remains **NO-GO**.
