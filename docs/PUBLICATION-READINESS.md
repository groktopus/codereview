# GitHub review publication readiness

**Decision: NO-GO. Publication remains disabled.** This record distinguishes local adapter evidence from hosted proof and states what must be produced before a narrowly scoped publication can be considered. It does not authorize a write.

## Evidence now available

The existing [`pr-review publish` command](CLI-PUBLISH-PREVIEW-MIGRATION.md) renders a validated preview and does not read GitHub credentials or write externally. `GitHubActionsPublicationAdapter.admit()` performs bounded API-bound checks for the open PR, analysis and publisher runs, selected result artifact, artifact digest, and exact result binding, then constructs a `PublicationAdmission` containing the PR/head/base, run identities, artifact hash, and admission-evidence hash ([implementation](../src/pr_review_harness/actions_publication.py)). The fake-transport suite exercises artifact admission, receipt handling, history limits, and one-shot submission behavior ([tests](../tests/test_actions_publication.py)); its new `admission_only` case proves the candidate can be built with read-only scopes and makes no POST or upload.

There is limited historical hosted read-only evidence for the analysis workflow: [run 36294682123](PRODUCTION-DELIVERY.md) checked PR 477's head and uploaded its result artifact, but ended `PARTIAL` / `INCOMPLETE`. This was not a publication admission run or a writer-capability observation. The central publisher workflow still has an unconditional hard stop at `if: ${{ false && vars.PR_REVIEW_PUBLICATION_ENABLED == 'true' }}` ([`.github/workflows/pr-publish.yml`](../.github/workflows/pr-publish.yml)). The App-backed provider, protected runtime composition, receipt protocol, and fake-transport tests exist; target-local installation and hosted writer proof do not.

Specialist detection evidence remains insufficient. Sanitized PR-457 run 36468167383 recorded six valid specialist reports with zero findings; PR-464 runs 36401670945 and [36517763840](experiments/model-only-shadow-run-36517763840.md) each recorded ten valid zero-finding reports. In 36517763840, the writer and upload stages projected `success`, but the shadow audit was `incomplete` / `no_writer_candidate`; Jev and both auditors made zero calls. This is green transport/report parsing paired with an incomplete audit, not a completed comparison or a semantic-quality result. The sanitized preflight binds that run to runner `c05ab8f`, before merged PRs #126 and #127. PR #126 added the artifact-recovery preview; PR #127 merged local-only private per-task diagnostics (not uploaded). These improve recovery and observability without closing the review-quality evidence gap. A next provider-free control can use fixed synthetic expected findings and scripted outputs to check that an omitted finding is surfaced as a test-oracle miss and that incomplete outputs remain incomplete. Such a control would validate sensitivity/safety plumbing only; it would not establish real-defect detection, recall, calibration, or production quality. The existing human-adjudicated gold evaluation remains unchanged.

## Blocking gaps and acceptance evidence

| Gate | Current state | Evidence required to close |
|---|---|---|
| Verified runtime identity and least privilege | **Partially implemented.** App identity canary/provider and a target-local Actions-token credential path are available in code; the read-only canary still reports writer capability as untested ([`ACTIONS-RUNTIME.md`](ACTIONS-RUNTIME.md)). Neither workflow YAML nor a typed identity proves that a write will succeed. | Bind exact protected workflow/run/attempt/repository/source facts. Keep App `VERIFIED` separate from Actions `PLATFORM_BOUND`; record Actions permission scope as a trusted workflow declaration. A confirmed, reconciled review observes only that exact effect. Read-only target settings evidence and fake tests do not substitute for that effect observation. |
| Owner authority and target selection | **Policy model selected; target binding missing.** Use narrow standing authorization for results matching an exact committed policy; do not require per-result human approval. | Before activation, bind numeric repository ID/name, protected default branch, workflow IDs/paths/refs, harness SHA, profile/provider identities, allowed disposition/body cap, finite history/deadline limits, and the `UNKNOWN` operator. Keep policy `enabled:false` until the separate concrete activation decision. |
| Hosted run and artifact admission | **Implemented in the protected composition and local adapter tests; hosted target path unverified.** | A protected hosted read-only preflight must retrieve only the selected artifact and emit a sanitized receipt with immutable identifiers/hashes/status. Preserve exact-run evidence for success and stale head, wrong run/attempt, missing/ambiguous/expired artifact, digest mismatch, and unavailable API cases. No review POST occurs in this phase. |
| Pre-POST receipt and replay history | **Implemented in fake-backed composition; hosted uploader/history path unverified.** The design requires an acknowledged `SUBMISSION_STARTED` receipt before one POST and complete bounded history reconciliation ([`ACTIONS-PUBLICATION-DESIGN.md`](ACTIONS-PUBLICATION-DESIGN.md)). | A protected rehearsal must show acknowledged receipt upload on the exact publisher run before POST, failed/ambiguous upload preventing POST, and incomplete history or ambiguous submission remaining `UNKNOWN` with no retry. Retain artifacts for the selected reconciliation horizon. |
| One-comment canary | **Not performed; effect remains disabled.** | After target/source/policy and read-only admission are verified, present one concrete non-blocking `COMMENT` effect, exact body hash and PR head, credential route, bounded one-attempt procedure, and rollback/UNKNOWN owner for the final approval. Verify response and read back one matching review ID, actor, commit, event, marker, and body hash. Any ambiguous outcome stops further writes. This is a single capability observation, not ongoing authorization by individual-result approval. |
| Disablement and rollback | **Current containment is effective:** the central publication job is hard-disabled. The target-local Actions-token template is also hard-disabled; its publisher job declares only `actions: read`, `contents: read`, and `pull-requests: write` so the exact effect route can be tested after separate owner review. | Keep the hard stop until the owner approves a reviewed activation. The rollback control is to restore the hard-disabled condition and remove the writer permission route; for the App path, revoke its installation credential. Verify the workflow cannot dispatch another writer. A posted comment may already have notified users; containment cannot undo that effect. Any removal or correction requires a separate owner-directed incident decision. |

The owner must also name the operator responsible for `UNKNOWN` reconciliation and define artifact access/retention and finite run, page, byte, and deadline limits before any canary. No automated check, fake transport, read-only hosted result, or model output can substitute for that owner decision. Until every gate has its named acceptance evidence, publication stays disabled and the decision remains **NO-GO**.
