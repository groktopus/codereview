# Model-only shadow audit v1

The shadow runner performs three bounded calls over one frozen case packet:

1. A source-only OpenAI-compatible auditor receives the frozen task and cited source evidence. Its output is sealed locally before Jev is called, and its request never includes the writer candidate.
2. The existing `ClaimAssessmentAdapter` asks Jev to classify that candidate against the same evidence.
3. A separate claim-facing auditor receives the candidate, Jev's typed classifications, and only the cited source evidence. It does not receive the source-only auditor output.

The CLI is `scripts/run_shadow_audit.py`. It requires `--live` before it can dispatch. It permits at most one call per stage, has per-request byte limits and a finite deadline, does not retry, execute target code, or publish a review. Run with a reviewed `model-only-shadow-case.v1` JSON packet, separate provider configs, a trusted TypeSafe decision config, and a new output directory. The emitted manifest contains statuses, identities, and hashes. Exact request and structured-response bytes remain in mode-0600 files beneath a mode-0700 output directory; do not upload those files as CI artifacts.

The packet must carry the full original snapshot. Its `snapshot_hash` is recomputed using the harness snapshot contract over every snapshot field other than `snapshot_id` and `snapshot_hash`. The frozen PR-457 trial material in `docs/real-case-trial-v1` contains its snapshot digest and evidence bindings, but not the full snapshot payload, so that material alone cannot be used to reconstruct or claim verification of the original snapshot.

The staged same-job continuation in `.github/workflows/private-shadow-capture.yml` is disabled. Its runner selects at most one candidate packet by the pinned writer-plan task order, then packet SHA-256 within a task; model-produced candidate text does not control selection. It permits three audit calls maximum, zero retries, 64 KB request and response caps, 1,800 output tokens per LLM call, and 90 seconds per call. If no packet contains a candidate, it makes zero audit calls and records an explicit `incomplete` result with all three roles `not_run`. The public artifact allowlist is a hash-and-status receipt; raw packet, request, response, and manifest files remain in the private job workspace and are deleted on job completion.

Do not enable the audit steps yet. Static identities and budgets are pinned, and each adapter validates the request at its own dispatch boundary, but the workflow does not yet provide a provider-free, secretless preflight for each stage. On activation, both config and dispatch steps must require a successful writer receipt and their matching stage-preflight result. The claim-auditor request depends on Jev's runtime response, so a precomputed hash for that future request would be fabricated; prepare and cap-check each request immediately before its stage. Controlled model-stage failures produce a terminal role state and a hash-only receipt. If packet/config validation or artifact I/O fails before a receipt can be written, sanitization fails closed, no audit artifact is uploaded, and the always-run cleanup removes the private workspace. A completed package would establish traceable model-only observations only, not accuracy, correctness, ground truth, or truth labels.

`pr-review review --private-shadow-capture DIR` now opts a fresh read-only review into a separate private capture directory. The directory must be new and separate from ordinary output. It stores the full frozen snapshot, task-local source evidence, bounded exact provider request bodies, exact structured message-content bytes returned by the provider, call receipts, and one `case-packets/*.json` file per admitted candidate or task without a candidate. The request and response files are mode 0600 under mode 0700 directories; they must never be uploaded as Actions artifacts. The ordinary result and stdout do not include those bytes. Failed or interrupted calls retain explicit incomplete/failed receipts rather than a fabricated response. This captures local request bodies and structured message content, not authenticated remote wire delivery or the full HTTP envelope.

Capture is disabled for resume, prepare-only, and dry-run. In GitHub Actions it requires the reviewed `groktopus/codereview/.github/workflows/private-shadow-capture.yml` manual workflow on `main`, an explicit trusted marker, and a new direct child of `RUNNER_TEMP`. A repository secret or PR input cannot select the capture destination. The workflow must verify its checked-out commit equals `GITHUB_SHA` before review dispatch; the capture option alone does not establish that property. The capture exporter checks that each candidate is from its own task-local provider response and admitted final finding, but the v1 shadow runner still declares the writer role from the packet. Until the separate deterministic packager verifies the packet and exact writer artifacts together with the three audit roles, do not claim a complete four-role v2 comparison.

All model judgments are advisory. Unknowns, abstentions, incomplete output, and failures remain explicit. These outputs do not establish accuracy, ground truth, or release readiness. The injection fixture verifies that source text is delivered as untrusted data and does not cross stage boundaries; it does not measure model resistance to prompt injection.

## Complementary evaluation when human labels are unavailable

Human adjudication is unavailable for this project. Do not leave it as a presumed future source of labels or use model-generated labels to fill that role. Retain any model-produced screen with `reviewer_kind: model_teacher`; `unknown` or missing provenance is never human. The model-only evidence track can qualify whether a bounded, read-only shadow was executed and audited. It cannot estimate semantic accuracy, precision, recall, error rates, calibration, or truth.

Use the roles for different questions, not as votes on one answer:

1. The writer LLM reviews the frozen case and trusted profile and emits candidate findings with stable IDs and source references.
2. Jev independently assesses each writer candidate against the same frozen evidence, keyed to that candidate ID. Preserve its typed decision, abstention, or failure exactly. Do not replace candidate-level assessments with an aggregate score.
3. A source-only LLM auditor reviews the frozen case without seeing writer findings, Jev results, prior teacher labels, or arm identity, and seals its result before either is revealed. This is a check for independently surfaced concerns and evidence gaps, not a complete oracle for missed findings.
4. A separate claim-facing audit may inspect a Jev assessment, its candidate, and the cited evidence. Because it sees the claim under review, label it claim-aware, not blind or prediction-blind. Keep it as a separate supplement unless a versioned contract can represent it without merging it with the source-only audit.

Freeze the case-selection procedure, source snapshots, profile, models, prompts, rubrics, request grouping, limits, and comparison rules before dispatch. Use both a natural-prevalence sample and a separately reported risk-enriched challenge set; never pool their counts. Preserve request and response hashes, role/model/runtime identity, prompt/rubric revision, case identity, and every role outcome. No live target writes or target-code execution are part of this evidence run.

Report per-case and aggregate denominators for writer candidates, Jev assessments, source-auditor observations, claim-audit records, deterministic reference checks, abstentions, disagreements, incomplete results, failures, and not-run roles. Include zero-candidate cases and missing roles. Describe model-to-model relations as observed agreement/disagreement only; do not convert them to correctness labels or use a vote/confidence threshold. A model disagreement stays unresolved until the human owner decides how the advisory should be handled. A source-auditor finding with no writer counterpart is an observed unmatched concern, not automatically a missed defect; a writer finding with no counterpart is not automatically false.

## Decision gates

**Read-only shadow entry.** Start only after the exact source/profile/model/prompt/limit bundle and cases are frozen, the run is authorized as read-only, capture storage is private and bounded, and deterministic preflight verifies source identity and configured limits. The incumbent review remains authoritative. Failure of any preflight check means do not dispatch.

**Read-only shadow qualification.** The package passes only when every selected case and role has exactly one explicit terminal state (completed, failed, incomplete, abstained, not run, or unavailable); all candidate IDs and role outputs reconcile; every source reference has an explicit deterministic snapshot/location/changed-range status; every required deterministic control reports a status; and there are zero safety/control invariant violations, zero configured-limit overruns, and zero cases where stale, partial, failed, or unknown required coverage is presented as current or complete. Unknown or missing checks fail this gate. Publish no review and change no disposition. This gate accepts traceability and bounded operation only, not model quality.

**Future advisory publication.** A read-only pass does not authorize publication. Before an owner may authorize a narrowly scoped, non-blocking advisory publication canary, require the qualified shadow package, exact current-head verification immediately before the write, least-privilege writer identity, tested duplicate/ambiguous-submit recovery, and deterministic effect receipts. The deterministic reducer remains authoritative for disposition and the union of accepted blockers; writer, Jev, and auditor outputs may never remove an accepted blocker or override its status. The publication artifact must preserve every accepted blocker ID and its evidence. For each additional claim eligible for publication, require a stable candidate ID, resolved in-snapshot reference and changed-range status, a completed candidate-bound Jev record, and a separately preserved source-only audit. Quarantine a claim when a required record is missing, incomplete, abstained, or structurally contradictory; do not resolve disagreement by voting. Record withheld claims and denominators. Keep publication explicitly advisory and unable to affect merge eligibility. Obtain a separate, explicit owner authorization for the live canary; successful deterministic checks and model agreement do not create that authorization or establish that a claim is true.

**Future cutover or Droid retirement.** Do not infer replacement quality from this model-only track. Before a reversible cutover decision, require repeated normal-workflow shadows on a frozen, owner-selected natural-prevalence sample and a second project/profile; complete model-role and deterministic-check accounting; no unresolved deterministic safety, freshness, coverage, or publication-control violations; documented operating cost/latency and abstention/disagreement distributions; an observed rollback/recovery rehearsal; and a named owner who explicitly accepts that semantic error rates and general accuracy remain unknown. Keep the incumbent available through the rollback window. Any model, prompt, rubric, or profile change invalidates the associated comparison and requires a new frozen run. This is an operational risk-acceptance decision, not a quality or calibrated-accuracy gate. If the owner requires a quantified quality claim, it cannot be made without independent labels.
