# Cross-model comparison v2

`review-cross-model-comparison.v2` adds a narrow, deterministic check to the v1 advisory comparison: when local response bytes are supplied, the verifier can confirm that a named reporter's bounded JSON response contains a typed relation and the cited record IDs at a declared JSON Pointer.

Every case retains four separately identified roles: `writer`, `jev`, `source_auditor`, and `claim_auditor`. The prediction-blind `source_auditor` output is preserved as its own run, call manifest, and records. It does not report a relation against Jev. The supported pairs are `writer_jev`, reported by Jev, and `jev_claim_auditor`, reported by the claim-facing auditor. This keeps the source-only review separate from an audit that sees Jev's claim.

Each run includes a `calls` array because one stage may make multiple provider calls. A call binds the request and complete response SHA-256 values to local artifact IDs. A call with an attempted request but no complete response uses `null` for both response fields. `calls_manifest_sha256` is the SHA-256 of the canonical JSON array: UTF-8, sorted object keys, compact separators, and Unicode emitted directly. It binds each member's IDs and hashes together. These hashes bind bytes to the declaration; they do not authenticate who produced or transmitted the bytes.

Each relation assertion binds its reporter role, run ID, call ID, response artifact ID, JSON Pointer, enum value, and applicable record IDs. The artifact must contain the exact structured response content bytes captured by the provider adapter before parsing or re-serialization. A local response is verified only if it is a regular file within the 4 MiB per-response and 64 MiB aggregate limits, has the declared hash, parses as bounded JSON, and its pointer selects an object whose relation and IDs exactly match the assertion. Missing bytes, unsafe file types, malformed JSON, a missing pointer, a hash mismatch, or different values remain explicit failures. No text matching or inferred relation is performed.

The report preserves per-role run status and record denominators, zero-call and missing-response counts, pair relation denominators including `UNKNOWN`, and response verification states. Empty candidate sets remain zero-record observations. An absent assertion is not converted to a success. A verified response proves only that the bytes contain the declared typed fields at that location; it does not prove that the relation is semantically true, that an asserted match is substantively correct, or that any model is accurate. The report sets accuracy, ground truth, calibration, and correctness claims to `null`.

Use `pr_review_harness.cross_model_v2.validate_cross_model_comparison_v2(value, corpus)` for structural and corpus-identity validation, then `compare_cross_model_v2(value, corpus, artifacts={artifact_id: Path})` to check supplied bytes. The offline CLI is `scripts/compare_cross_models_v2.py`; it makes no provider calls.
