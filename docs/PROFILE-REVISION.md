# Production context profile revision

The candidate generic and SlopSearX profiles are versioned `generic-production-v2` and `slopsearx-production-v3-check-bindings`. The historical pilot used the retained v1 profiles; comparisons must report this intentional profile change and its content hash rather than claiming model-only changes. The SlopSearX v3 revision replaces the unresolved combined check binding with separate exact-name, exact-app bindings for `portal-contract` and `portal-browser`.

`context_paths` remains a small set of initial exact-path seeds. `retrieval_context_patterns` is a separate operator-authored allowlist for bounded follow-up retrieval. Generic source/test/documentation roots and project manifests are permitted; SlopSearX explicitly permits its application, engine, tests, documentation and deployment paths. These patterns do not grant filesystem access outside immutable repository objects or permit code execution. A permitted path is not automatically relevant or reviewed.

Only explicitly named policy documents are marked through `trusted_policy_paths`: generic AGENTS.md, and SlopSearX AGENTS.md/CONTRIBUTING.md. Implementation, tests and other documentation remain repository evidence even when read from BASE. Immutable provenance establishes which content was read, not instruction authority or correctness.

Retrieval still defaults to BASE. HEAD retrieval requires a separate explicit trusted revision policy. Both revisions and any missing counterpart must remain visible when introducedness or caller compatibility depends on a comparison. The initial change does not imply a symbol/call-graph adapter, full repository review, or observed coverage improvement; those must be demonstrated in actual runs.

The check-binding revision is based on retained read-only GitHub evidence for PR 464 at head `bffc26f9e4bf95aca0c252e88a2396d03ece854c`: the complete 20-run envelope contains exactly one completed successful `portal-contract` run and one completed successful `portal-browser` run, both from GitHub App ID `15368`. The profile keeps the existing `portal-impact-evidence` ID attached only to `portal-contract` and adds `portal-browser-evidence` for the browser journey. The two checks remain separate evidence; neither is represented as a combined semantic pass. Ingestion against the retained envelope yields PASS for each exact binding. This is CI evidence for that immutable head only, not code-review quality, target execution by this harness, or a release gate.

Context-selection experiments are documented in [CONTEXT-SELECTION.md](CONTEXT-SELECTION.md). A full-applicability preflight did not fit the existing per-request limit; a narrower trial that omitted applicable policy was rejected. No context-selection experiment is enabled in this profile.
