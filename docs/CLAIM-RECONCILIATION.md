# Opt-in claim reconciliation

Profiles may opt into `claim_reconciliation` with version `claim-reconciliation.v1`, `enabled: true`, `required: true`, and an integer `max_assessments` from 1 through 4. The CLI must supply the same `--max-claim-assessments` value and a decision-provider configuration. Missing or mismatched configuration fails before review work starts. Profiles without this object retain the prior optional shadow behavior and policy fields; the new runtime source fingerprint changes with this code, so old checkpoints still fail exact runtime identity validation.

The deterministic reconciler binds the primary semantic assessment hash, candidate and evidence hashes, and the exact native claim request hash. `AGREES` means the available comparable support, materiality, and introducedness dimensions match the primary assessment and the missing-context qualifier is satisfied. `missing_context` has no primary-side field, so it is always recorded in `uncompared_dimensions`, never described as agreement between two assessments. An identified or uncertain context gap makes the result partial unless a comparable dimension also disagrees, in which case the result is conflict; the qualifier remains separately visible. An unavailable required answer, invalid response, failed call, or exhausted cap is partial.

This stage cannot promote a candidate to an accepted finding. It also cannot remove an existing accepted blocker: a disagreement or incomplete reconciliation adds required partial coverage, while the finding and reducer result preserve the primary blocker. Probabilities remain observations with no threshold or calibration claim. The reconciler is deterministic policy glue, not a second source of truth.

`profiles/slopsearx-v14-jev-reconciliation-candidate.json` is an unqualified candidate profile for bounded testing. A local trial would use `--profile profiles/slopsearx-v14-jev-reconciliation-candidate.json --max-claim-assessments 1 --decision-config <trusted-config>`. This candidate profile is not a deployment or cutover instruction; it has no target binding and grants no new provider authorization.
