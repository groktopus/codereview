# Secretless hosted cancellation and resume rehearsal

The observed two-run evidence is recorded in [Hosted recovery drill evidence — 2026-09-27](HOSTED-RECOVERY-DRILL-EVIDENCE-2026-09-27.md). The protocol below remains the procedure and scope definition; the supplement records one synthetic rehearsal outcome only.

This manually operated, read-only Actions drill exercises the packaging and recovery boundary using a synthetic two-commit Git repository and a loopback fake provider. It does not read target SlopSearX code, bind provider credentials, publish a review/check/comment, or change the normal analysis workflow. Run A builds the wheel from the exact checked-out source using pip's isolated PEP 517 environment and project-declared `setuptools>=68`; the backend patch version is not pinned. `--no-deps` prevents project runtime dependency installation.

## Dispatch procedure

Use canonical `main` and the same reviewed full commit SHA for both workflow runs. The workflow checks out `github.sha`, verifies `HEAD` equals it, and rejects refs other than `refs/heads/main`. If `main` moves between runs, stop; do not substitute another SHA. The protocol is limited to two workflow runs total: one Run A, one Run B, one cancellation, and no retries.

1. On the exact candidate `main` commit, dispatch **Secretless hosted recovery rehearsal** with `phase=run-a` and no `source_run_id`.
2. Starting immediately, poll only that exact run's metadata and artifact list at intervals of at least 10 seconds. Allow at most 240 seconds from first observing the run as `in_progress` for the readiness artifact to appear; stop polling if the run ends. Confirm it is the canonical workflow, repository, `main` ref, and exact dispatched SHA. Find exactly one unexpired `hosted-recovery-ready-<run-id>` artifact owned by this run. Download only that artifact within a 64 KiB transfer cap and 60-second deadline. Verify the archive contains exactly one non-directory `readiness.json` entry (at most 2 KiB; ZIP mode may be permission-only/unspecified or regular-file, never a special file), then check its run/attempt, repository, workflow path/ref, source SHA, aggregate source-module hash, checkpoint hash and byte count, snapshot/request identity, held deadline, ordinal 2 in flight, one completed and one unsettled reservation, and zero expected resume requests. The `HOSTED_RECOVERY_READY` log notice is supplementary only: GitHub may not expose it while the step is running, so its absence must not block a valid API-verified readiness artifact. If the run ends, the artifact cannot be independently listed/downloaded within the bound, or any identity check fails, do not cancel; preserve evidence and stop.
3. Only after that active-run readiness retrieval succeeds, cancel that exact Run A. Never cancel another run. The helper's absolute held-request deadline is 450 seconds after setup inside a 480-second shared deadline; readiness upload is bounded to 45 seconds of that same deadline. If readiness setup, upload, or independent retrieval misses its limit, preserve the run and stop.
4. Confirm Run A concludes `cancelled` and its distinct `hosted-recovery-<run-id>` final artifact exists. Record artifact ID/name/size/expiration and verify it contains the manifest, checkpoint, fixture bundle, bounded provider ledger, readiness record, and original wheel. A missing final artifact is a failed drill. Run B independently validates the source run and both artifact metadata identities before downloading/extracting the final artifact, then compares the embedded readiness receipt against the separately retrieved readiness artifact identity/hash/size.
5. Dispatch **Secretless hosted recovery rehearsal** from the same full SHA with `phase=run-b` and `source_run_id` equal to Run A's numeric ID. Do not retry Run B.
6. Inspect Run B's `hosted-recovery-resume-<run-id>` artifact. It must report `INCOMPLETE`, preserve the first succeeded result, preserve the interrupted call as `INTERRUPTED_UNKNOWN`, retain two historical/reserved calls, and record exactly zero new provider requests. This is the expected contract: the uncertain in-flight operation is not replayed or falsely reported complete.

## Bounds and evidence

Each job has a 15-minute timeout. Run A's helper uses a 480-second shared wall deadline, waits up to 180 seconds for the in-flight checkpoint, and holds until its absolute 450-second deadline. Readiness artifact upload is capped at 45 seconds within that shared deadline. Node setup and locked npm setup each have two-minute timeouts; `npm ci --ignore-scripts --no-audit --no-fund` runs with Actions runtime artifact credentials blank. The checked-in Node action receives the runtime artifact environment as an action, validates it and its inputs, and forwards only an explicit allowlist plus required run identity to the Python helper. Provider credentials and `GITHUB_TOKEN` are not forwarded. SIGTERM to the helper is converted into orderly interruption; its `finally` path terminates and waits for the separately grouped fake CLI process before shutting down the loopback server. This bounds helper-owned detached work on abnormal action timeout/output termination as well as workflow cancellation, subject to runner hard-kill limits. Run B has a 540-second shared deadline for metadata, bounded download, extraction, wheel installation, resume, and cleanup; the CLI resume itself is bounded to 12 seconds. Other setup/build steps have two-minute limits.

Final transfer content is capped at 7.9 MB (leaving archive overhead below 8 MB), with at most eight regular files and at most 6 MB per file. Final archive retrieval is capped at 7.9 MB and 150 seconds; readiness retrieval is capped at 64 KiB and 60 seconds. Metadata responses are capped at 256 KiB and 30 seconds. Extraction rejects paths, duplicates, directories, symlinks, unexpected names, and oversized entries. The original validly named wheel is transferred, hash-checked, and installed in Run B; no independent rebuild hash comparison is made because wheel timestamps can vary. The fake provider binds only to loopback port 18765, returns one synthetic response, and holds its second request until cancellation.

Run A records immutable base/head commits and snapshot/request identity, exact source commit and module hashes, profile and limits hashes, original wheel SHA-256, checkpoint SHA-256, and an allowlisted prior provider-call ledger. The separate readiness receipt carries run/attempt/workflow/source/checkpoint identity and aggregate source-module hash, without secrets or configuration values. Run B checks canonical repository, workflow path, dispatch event, `main`, unchanged source SHA, canceled conclusion, run ID, and both artifact names/IDs before bounded download. It then verifies remaining identities before installing the transferred wheel or resuming. The checkpoint's unresolved provider reservation must remain `INTERRUPTED_UNKNOWN`; it must not trigger a new request. Historical request counts are read from the retained ledger; zero-new-request evidence concerns Run B only. Hashes detect accidental or partial substitution, but are not a digital signature against replacement of both payload and manifest.

Record both run IDs/links, exact source SHA, both artifact metadata records, proof that readiness was listed and downloaded while Run A was in progress, cancellation event/conclusion, artifact file list and digests, Run B identity checks, CLI outcome, historical provider ledger, and zero-new-request result. The readiness artifact uses the existing uploader's configured seven-day retention; final and resume artifacts use one-day retention. GitHub may not expose an artifact before a run completes. Failure to retrieve readiness while Run A is active means do not cancel; the notice is not a substitute. After cancellation, GitHub can escalate SIGINT to SIGTERM and kill the process tree or forcibly terminate the job; `always()` is an attempt, not a retention guarantee after runner loss, hard termination, or service failure.

## Stop and rollback

Stop immediately on a secret binding, external provider request, unexpected network access, repository/check/PR write, identity or size mismatch, missing readiness/checkpoint proof, extra provider request, exhausted deadline, or any attempted repeat. Preserve logs and artifacts, record failure without retry, and remove this dedicated workflow through the normal reviewed change process if it causes unintended behavior. The production reusable workflow remains unchanged.
