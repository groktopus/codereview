# Secretless hosted cancellation and resume rehearsal

This is a manually operated, read-only Actions drill for the packaging and recovery boundary. It uses a synthetic two-commit Git repository and a loopback fake provider. It does not read SlopSearX or other target code, bind provider credentials, publish a review/check/comment, or change the normal analysis workflow. Run A's wheel is built from the exact checked-out source using pip's isolated PEP 517 environment and the project-declared `setuptools>=68` build backend; pip may resolve a newer compatible backend from its trusted package index. The backend patch version is not pinned. `--no-deps` prevents installation of project runtime dependencies.

## Dispatch procedure

Use canonical `main` and the same reviewed full commit SHA for both workflow runs. If `main` moves between runs, stop; do not substitute another source SHA. Keep the workflow page open so Run A's log can be monitored. The expected full procedure is:

1. On the exact candidate `main` commit, dispatch **Secretless hosted recovery rehearsal** with `phase=run-a` and no `source_run_id`.
2. Wait for the log notice `HOSTED_RECOVERY_READY`. It reports the workflow run ID, staged checkpoint digest, fake provider ordinal 2 in flight, one completed reservation, and one unsettled reservation. The adjacent JSON status reports the staged artifact byte count. Do not cancel before that notice appears; if it never appears, do not cancel and mark this single attempt failed.
3. Cancel only that exact Run A workflow from its run page. Do not cancel any other run. The run waits at most 450 seconds for this operator action after setup. If it times out, preserve the failed run and stop.
4. Confirm Run A is canceled and its `hosted-recovery-<run-id>` artifact exists. Record the artifact ID/name/size/expiration and confirm its contents include the manifest, checkpoint, fixture bundle, bounded provider ledger, readiness record, and original wheel. A missing artifact is a failed drill. Run B independently checks the source run metadata and artifact metadata before downloading or extracting it.
5. Dispatch **Secretless hosted recovery rehearsal** again from the same full commit SHA with `phase=run-b` and `source_run_id` set to Run A's numeric run ID. Do not retry Run B.
6. Inspect Run B's `hosted-recovery-resume-<run-id>` artifact. It must report `INCOMPLETE`, preserve the first succeeded result, preserve the interrupted call as `INTERRUPTED_UNKNOWN`, report two historical/reserved calls, and record exactly zero new provider requests. The unchanged incomplete result is the expected behavior: the uncertain in-flight provider operation is not replayed.

## Bounds and evidence

The workflow allows at most two Actions runs: one Run A, one Run B, one whole-run cancellation, and one resume. Each job has a 15-minute timeout. Run A's helper has a 480-second shared wall deadline, allows at most 180 seconds to reach readiness, and stops waiting at 450 seconds to leave cleanup and artifact-upload time. Run B has a 540-second shared wall deadline including metadata reads, bounded archive download, extraction, wheel install, resume, and cleanup; the CLI resume itself is bounded to 12 seconds. Setup/build steps each have a two-minute timeout. The transfer file content cap is 7.9 MB (leaving archive overhead below 8 MB), with at most eight regular files, each at most 6 MB. The archive download is capped at 7.9 MB and 150 seconds; metadata responses are capped at 256 KB and 30 seconds. Extraction rejects paths, duplicates, directories, symlinks, unexpected names, and oversized entries. The original validly named wheel is transferred and its digest and installed module hashes are checked in Run B; no second build is compared. The fake provider has a fixed local identity and key, and only runs bound to loopback port 18765. It returns one synthetic response and holds the second request until cancellation.

Run A records immutable base/head commits and snapshot/request identity, exact source commit and module hashes, profile and limits hashes, original wheel SHA-256, checkpoint SHA-256, and an allowlisted prior provider call ledger. Run B checks the exact canonical repository, workflow path, workflow-dispatch event, `main` branch, unchanged source SHA, canceled conclusion, run ID, and artifact name before bounded download and extraction. It checks the remaining identities before installing the transferred wheel or resuming. It verifies that the checkpoint's single unresolved provider reservation becomes `INTERRUPTED_UNKNOWN`; it must not redispatch that call or any other request. Hashes bind the contents against accidental or partial substitution inside the downloaded artifact. They are integrity evidence, not a digital signature against a party able to replace both data and manifest.

Record links/IDs for both runs, the exact source SHA, artifact metadata, cancellation event/conclusion, readiness log, artifact file list and digests, Run B identity checks, final CLI outcome, historical provider ledger, and zero-new-request evidence. Keep the Action logs and both short-retention artifacts as the evidence packet. An artifact upload step marked `always()` is attempted after cancellation, but GitHub may escalate cancellation from SIGINT to SIGTERM and kill the process tree, and can forcibly terminate cancelling jobs/steps after its cancellation timeout. Therefore a missing upload fails this rehearsal; no claim is made that `always()` guarantees retention after runner loss, hard termination, or service failure.

Stop immediately on any secret binding, external provider request, unexpected network access, repository/check/PR write, artifact identity or size mismatch, missing checkpoint/readiness proof, extra provider request, or any attempt to repeat either run. Preserve the failure logs/artifact, do not retry, and disable/remove this dedicated workflow in the reviewed branch if it causes unintended behavior. The production reusable workflow remains unchanged by this rehearsal.
