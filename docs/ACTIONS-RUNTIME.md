# GitHub Actions canary runtime

The publication workflow is still read-only: its review-writing job is hard-disabled. The canary checks repository, workflow-run, PR, and current PR-head bindings through GitHub's read API, then uploads only a small `safe_to_publish: false` diagnostic artifact. The check never grants or infers a writer capability.

The canary runs as a local Node 24 action. GitHub's current `NodeScriptActionHandler` injects `ACTIONS_RUNTIME_TOKEN` and `ACTIONS_RESULTS_URL`; its shell `ScriptHandler` does not. The action forwards an explicit allowlist to a bounded Python child and suppresses child stderr. That child gives only the runner artifact-runtime fields to the pinned `@actions/artifact` SDK process, with a fixed HTTPS host policy, output cap, deadline, and process-group cleanup. Provider secrets and actor-context variables are excluded.

Canary receipt v2 also records hash-only local runtime provenance. Before its GitHub API reads, the Python child checks that its loaded module comes from `GITHUB_WORKSPACE/src/pr_review_harness`, Git `HEAD` matches the platform `GITHUB_SHA`, tracked package sources are clean, and the on-disk Python module set matches that commit. It reports the source revision, module count, and SHA-256 of the package module tree; it uploads no source files or source text. Any mismatch yields `UNKNOWN` and skips the API reads. This establishes checkout and source-tree integrity for that process, not token permissions, authenticated writer identity, or publication capability.

The artifact bridge pins the published `@actions/artifact` 6.2.1 package in `package-lock.json`; the bridge's `package.json` requires Node `>=22` for its locked dependency tree, and the workflow uses Node 24. The lock was generated from the npm registry with `npm install --package-lock-only --ignore-scripts --no-audit --no-fund` and checked offline afterward. No install script is needed. The local tests use a fake SDK and fake GitHub transport; they do not make a GitHub API call or upload an artifact.

Hosted runtime behavior remains unverified. Before considering publication wiring, an explicitly approved read-only canary must verify the actual runner runtime variables, the v2 runtime-provenance fields, exact GitHub run/API response bindings, artifact acknowledgement, and the configured API-token identity behavior. The receipt keeps `write_permission: NOT_TESTED` and `publication_capability: UNAVAILABLE`; read access does not prove permission to create reviews, and `GITHUB_ACTOR` is not accepted as writer identity. No hosted canary has been run and no write path is enabled.
